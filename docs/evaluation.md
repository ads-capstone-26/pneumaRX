# 精简实验报告

实验日期：2026-11-08。模型：gpt-6.1-terra。24 道 EHRSQL 风格定向题（18 可回答、6 不可回答），原版 Seeker、Direct SQL、受控 RX 各运行一次，共 72 次。参考结果由 SQL 与 Pandas 独立交叉核对，题目、数据与候选证据保持一致。

| 组 | 正确交付 /18 | 正确拒答 /6 | LLM token | 平均每题耗时 |
|---|---:|---:|---:|---:|
| Seeker | 16（严格格式/精度） | 6 | 1,371,006 | 22.98 秒 |
| Direct，无 IntentSpec | 18 | 6 | 171,664 | 3.13 秒 |
| RX，复核前 | 18 | 6 | 348,338 | 22.21 秒 |
| RX，复核后 | 18 | 6 | 449,401 | 32.64 秒 |

RX 前后为同一次执行的两个阶段，成本不能相加。token 包含全部题及拒答，不含 embedding 与启动失败。

**修复效果：** 修复同结构表元数据丢失和评测格式指令干扰后，RX 从 16/18 恢复到 18/18；含复核 token 从 437,587 增至 449,401（+2.7%）。简单查询、多表、时间聚合三层均为 6/6，原先多表层为 4/6。

**成本与准确率：** RX 比 Seeker 节省 67.2% token，但成本是 Direct 的 2.62 倍。Direct 同样全部答对，因此尚未证明 IntentSpec 提高生成准确率。

**Seeker 评分说明：** 原生文字回答由本地离线转录核对，不从中间结果补数。两项严格失分来自额外诊断列和最终数值舍入；按明确的目标列核查，两题计算值均正确。若只评价请求的计算值，三组均为 18/18；不能将格式差异解释成 RX 的 SQL 语义优势。

**复核：** 本轮 18 个正确候选全部通过，误拦截 0/18，额外消耗 101,063 token。没有自然错误候选，错误拦截率不可估计。修复前另有 16 个正确/构造错误输入：拦截 8/8 错误、误拦截 0/8 正确结果；这是历史补充实验，本轮未重复，不能外推为普遍 100% 拦截率。

**边界与可核查性：** 这是同一开发题集的修复回归，不是官方 EHRSQL 或未见题验证。受控 RX 使用冻结候选，关闭 UMLS、记忆和上游调整；保留一次 SQL 修复和 hybrid reviewer。单次运行的成本、时间与模型输出可能波动。完整请求、SQL、结果、源码/输入哈希与 token 账本保留在本地，不随本分支发布。

**本次额外开销：** 正式 LLM 1,992,071 token；本地注册失败后重试额外 17,337；embedding 822，已记录总计 2,010,230。另有沙箱连接失败未返回 usage，单独留档，不假定实际计费为零。
